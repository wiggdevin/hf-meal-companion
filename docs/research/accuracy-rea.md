# Accuracy mechanisms: bounded REA study

Prepared 2026-11-14 for `feat/accuracy-rea`. This study used the installed REA 6.9.0 CLI on public shipped Mealie and Tandoor JavaScript. It also read focused public source and the same-day primary-source harvest from the preceding research. No private health records, authenticated product account, paid API, or production database entered the study. No third-party implementation was copied into the app.

The useful result is a set of measurement and quantity contracts. The evidence does not establish any vendor's accuracy on Meal Companion's inputs. It does not recover proprietary expenditure, food-recognition, or database algorithms.

## Mechanisms and verification contracts

### 1. Quantity interpretation stays separate from display

**Observed:** Mealie's helper keeps numeric quantities and standard-unit dimension metadata, then selects a display unit and rounds for presentation. REA identifies its conversion function at `CkBlyt9b.js`, line 1, columns 5665–5901, node `jsrg_node_be37611df637ccdb5826800332bd35eb496fccb89e2e46125016f41aef27ccbe`. Its input gate at columns 4552–4746 requires quantity and standard-unit metadata. Its original-text function at columns 2618–2711 prefers the imported text when present. Tandoor's source permits base conversions within mass or volume, while food-specific custom conversions can bridge known units.

**App contract:** Parse explicit mixed/vulgar fractions and mass aliases into numbers. Use exact mass conversion factors for nutrient arithmetic. A volume or count needs a usable portion row for that food before it yields grams. Preserve an unresolved quantity rather than substituting water density or a standard 100 g. Unsupported ranges and negative amounts need explicit rejection or a structured representation, never silent reinterpretation.

**Verification:** Cover `1 1/2 cups`, `1½ cups`, `½ whole`, kilograms, milligrams and pounds; a `0.5 cup` portion row must scale by its labelled amount. A cup without a food-specific portion stays null. A fraction of one whole is an explicit amount and must not trigger the “no amount supplied” path. Guard negative and range inputs. Test the nutrient result from the original numeric quantity, not a rounded display string.

**Branch mapping:** The implementation driver reported red/green tests for `lib/capture/quantity.ts` and the explicit-fraction follow-up change in `lib/capture/follow-ups.ts`; this study inspected that diff and found it consistent with these contracts. The implementation driver owns the test receipts and final verification. This is an independent implementation, not translated Mealie/Tandoor code.

### 2. Evaluate food identity before conditional portion error

**Observed:** Nutrition5k supplies per-ingredient identities/masses and separate per-dish nutrient fields. Its published evaluator computes MAE and a percentage normalized by the mean reference value. It loops over prediction IDs; it does not independently establish a complete expected-case denominator. Its percentage metric is not mean per-item absolute percentage error.

**App contract:** Make expected cases explicit. Match foods one to one under a reviewed identity rule, then score gram error only on correct-identity pairs with measured or explicitly stated gram gold. Report misses, extras, wrong identity, quantity abstention, and the conditional gram denominator alongside that error. Missing gold is not zero. Author-guessed portions must not become measured mass truth.

**Verification:** A rice prediction labelled pasta must fail identity even at the right mass. Duplicate predictions must not match the same expected food twice. Missing predictions must lower recall and appear in the case receipt. Separate zero/missing nutrient gold and distinguish printed-label transcription from derived nutrient totals. Hold all views of a Nutrition5k plate in the same split; label the dataset domain in every result.

### 3. Source provenance and nutrient completeness travel with the value

**Observed:** Cronometer's documentation distinguishes composition datasets, branded label records and private custom foods. Mealie's inspected nutrition component stores nullable fields and labels its nutrition display per serving. Neither observation establishes nutrient correctness. Meal Companion already carries `revisionId` in `lib/capture/grounding.ts`; the prior audit also verified catalog source revisions and null handling.

**App contract:** Reuse the existing source/revision authority. Evaluation receipts should identify the catalog revision and record type, preparation state and known nutrient coverage. A printed zero remains zero. A missing micronutrient remains unknown. A corrected ingredient/portion must recompute from the confirmed record and quantity, with the original evidence available for review.

**Verification:** Use the same food name with distinct raw/cooked and branded/generic gold records. Check exact revision provenance in the receipt. Confirm that blank label fields cannot become zeros and that a correction does not retain a total calculated from the old food or portion. Exposing more provenance on the confirmation UI remains a product hypothesis, not a defect proved by this study.

### 4. Uncertainty concerns a particular stage

**Observed:** ingredient-parser gives text spans, amount flags and token confidence. LogMeal documents recognition confirmation separately from asynchronous depth quantity. MacroFactor documents pauses under insufficient data and distinguishes partial logs from absent days. None supplies calibration data for this app.

**App contract:** Keep identity certainty, quantity availability, label transcription, catalog nutrient coverage and final confirmation separate in evaluation. Model confidence alone must not establish grams or nutritional truth. An abstaining system needs both error and coverage reported. A method without labelled media must show that evidence gap in its denominator/status.

**Verification:** Include confident wrong-portion outputs, a correct food with unknown grams, an unreadable label and a missing media file. Confirm that each produces its own status and that no skipped input can improve the reported accuracy. Existing thresholds remain unchanged until held-out calibration supports a change.

### 5. Scale and confirm the same state

**Observed:** Tandoor's shipped table constructs the shopping amount as numeric ingredient amount times `ingredientFactor`, retaining food and unit, and uses that factor for display. REA node `jsrg_node_479966e8e5bc3055f4a51aeec4a4723f29fcf89caa1fea68b5368ff70f608aef` covers that request builder at line 1, columns 1924–2161. Its number-scaler function `jsrg_node_8ace76a3ea48b7406a4961aedcac97fe728596ee554ca65090efb648838204c8` supports half/double edits before a confirm event. These are static frontend observations; server persistence is unknown.

**App contract:** For capture or coach edits, judge the confirmed numeric state, source identity and requested amount together. A success sentence does not prove the requested mutation occurred. Preserve a correction as a state change and check the resulting log and totals. This verification contract is a local design choice; this study did not recover a commercial coach implementation.

**Verification:** Replay “half of that”, change food identity without changing amount, cancel a correction, and repeat a submitted confirmation. Compare the final state and action receipt with the intended mutation and confirm that no duplicate action occurs. Keep these state checks separate from prose/behavioral judging. Reuse the app's existing dispatch and receipt protections rather than inventing a second write path.

### 6. Test propagation before changing the adaptive engine

**Observed:** MacroFactor's public guidance treats partially logged days as a distinct input problem. The existing Meal Companion audit identifies a deterministic, account-seeded expenditure engine and calls for offline input-error tests. No proprietary estimator was recovered or compared.

**App contract:** Keep the existing estimator. Use synthetic complete days to isolate constant intake bias, a mid-series bias shift, omitted fats, false-complete days and missing records. Record estimator version, seed and scenario assumptions. Distinguish the estimate from proposal eligibility/hold reasons.

**Verification:** Re-run the same weight trajectory with one changed intake mechanism at a time and compare estimate/proposal outputs. These tests demonstrate sensitivity under stated assumptions, not real-world expenditure accuracy. OR-Tools remains an optional offline planner oracle if a measured feasibility gap later justifies it.

## Evidence status and stop condition

The bounded static/source/docs study is complete. No authenticated runtime scenario ran: Mealie's crawl returned an empty-page result, the guessed Tandoor demo host did not resolve, and the documented demo auto-login URL returned an interstitial. Public HTML and scripts remained readable without login, which supplied the shipped artifacts above. The study made no attempt to bypass the interstitial. It did not use REA browser capture, recover server algorithms, execute the Python packages, benchmark a vendor, or measure current production accuracy.

A TypeSafe Jev advisory check returned model `jev-1.14.0`. It rejected the claim that this work recovered MacroFactor's algorithm and remained uncertain on the positive summaries (supported probabilities 0.09–0.41). Those responses do not validate the mechanisms. Exact inspected source and retained REA ranges support the bounded static statements; runtime and backend claims remain unknown.
